\subsection{Repeated fixed-policy queries}
The 63 inputs comprise three primary 1,000-query streams on a 512-cell view; 54 geometry streams varying size ($d=64,512,2048$) and row overlap; and six generated-log streams with 64 actions, one million O and four million R events. The latter two groups contain 100 queries per stream. Queries vary nearby and unrelated policy directions at $\delta=.001$. Primary streams have one solve and 999 reuse hits, all true; others include false and unknown answers. These controlled workloads do not estimate online hit rates.

Four plans toggle screening $S$ and retention $P$, using identical solvers, candidate order and checker; answers, evidence and solver paths must match. The optimized implementation retains decoded views, feasible points and within-query number conversions, and skips zero coefficients. Thus the retention comparison isolates saving the exact terms in~\eqref{eq:scaled}. A separate candidate-order control checks the last solver certificate first; changing this order can change the returned certificate.

Service includes initialization, validation, all queries and fallback, serialization and checking with a 16-entry bank; it excludes ingestion, disk I/O, compression, network transfer and archival audits. A quality pass checks 45,000 responses; five shuffled timing rounds contribute 225,000 more. Each fresh run uses one CPU/native thread. Ratios compare enabled/disabled cost on the same input with the other switch fixed; group summaries give each input equal weight in a geometric mean. Rounds reflect machine variation. Individual costs, slow cases and all four conditional comparisons are archived.
